# Troubleshooting & Runbook: Zsh History Substring Search Widget Error

## Problem

When launching or using an interactive Zsh shell across target operating systems (Fedora, Arch Linux, Ubuntu, macOS, or fresh installations before bootstrapping), pressing the **Up Arrow** or **Down Arrow** keys outputs:
```text
No such widget `history-substring-search-up'
No such widget `history-substring-search-down'
```
In severe cases, arrow-key history recall is completely broken, leaving the shell unable to navigate command history.

---

## Root Cause

1. **Unconditional Widget Keybinding (`bindkey`)**:
   In Zsh, `bindkey '<seq>' <widget-name>` registers key sequences to widget names without verifying if the widget currently exists in ZLE (Zsh Line Editor). The command exits with status 0 even if `<widget-name>` is undefined.
   When the user subsequently presses `Up` (`^[[A` or `^[OA`) or `Down` (`^[[B` or `^[OB`), ZLE attempts to execute the missing widget and triggers runtime errors:
   `No such widget history-substring-search-up` and `No such widget history-substring-search-down`.

2. **Fragile Plugin Discovery & Missing Cross-Distro Sourcing**:
   - `core/home/.zshrc` previously only looked for Antidote at `$HOME/.antidote/antidote.zsh`. When users configured custom `ZDOTDIR`, installed Antidote via system package managers (`/usr/share/zsh-antidote` on Arch, `/usr/share/antidote` on Debian/Ubuntu), or used Homebrew (`/opt/homebrew/share/antidote` on macOS), Antidote failed to load.
   - The compiled static bundle (`~/.config/zsh/plugins.zsh`) generated by `setup_zsh.sh` was ignored if the Antidote runtime was not loaded in memory.
   - Distro-native package installations (e.g. `pacman -S zsh-history-substring-search`, `dnf install zsh-history-substring-search`, `apt install zsh-history-substring-search`, or `brew install zsh-history-substring-search`) were not auto-discovered as fallbacks.
   - If Antidote had not yet run or the machine was offline on initial clone, no plugins were sourced, leaving the widgets unregistered while `bindkey` still bound them.

---

## Implemented Solution

### 1. Robust Multi-Distro Plugin Loader (`core/home/.zshrc`)
- **Pre-configured settings**: Set plugin flags (such as `HISTORY_SUBSTRING_SEARCH_ENSURE_UNIQUE=1` and `ZSH_AUTOSUGGEST_*`) before plugins are sourced.
- **Universal Antidote detection**: Searches across standard paths:
  - `${ARCHCONFIG_ANTIDOTE_DIR:-}`
  - `${ZDOTDIR:-$HOME}/.antidote`
  - `$HOME/.antidote`
  - `${XDG_DATA_HOME:-$HOME/.local/share}/antidote`
  - `/usr/share/zsh-antidote` (Arch Linux / AUR)
  - `/usr/share/antidote` (Debian / Ubuntu)
  - `/opt/homebrew/share/antidote` (macOS Apple Silicon)
  - `/usr/local/share/antidote` (macOS Intel)
- **Static bundle fast-path**: Sources `~/.config/zsh/plugins.zsh` directly if newer than `plugins.txt` or if Antidote is absent.
- **Cross-distro fallback resolution**: Checks system-wide distro paths for `zsh-history-substring-search`, `zsh-autosuggestions`, and `zsh-syntax-highlighting` across Arch, Fedora, Debian/Ubuntu, and macOS Homebrew.

### 2. Defensive Keybindings with Graceful Fallback
Keybindings now inspect the ZLE widget table before binding:
```zsh
if (( ${+widgets[history-substring-search-up]} )) && (( ${+widgets[history-substring-search-down]} )); then
    bindkey '^[[A' history-substring-search-up
    bindkey '^[[B' history-substring-search-down
    bindkey '^[OA' history-substring-search-up
    bindkey '^[OB' history-substring-search-down
    [ -n "${terminfo[kcuu1]:-}" ] && bindkey "$terminfo[kcuu1]" history-substring-search-up 2>/dev/null || true
    [ -n "${terminfo[kcud1]:-}" ] && bindkey "$terminfo[kcud1]" history-substring-search-down 2>/dev/null || true
    bindkey -M vicmd 'k' history-substring-search-up 2>/dev/null || true
    bindkey -M vicmd 'j' history-substring-search-down 2>/dev/null || true
else
    # Fallback to standard line / history navigation if history-substring-search is unavailable
    bindkey '^[[A' up-line-or-history
    bindkey '^[[B' down-line-or-history
    bindkey '^[OA' up-line-or-history
    bindkey '^[OB' down-line-or-history
    [ -n "${terminfo[kcuu1]:-}" ] && bindkey "$terminfo[kcuu1]" up-line-or-history 2>/dev/null || true
    [ -n "${terminfo[kcud1]:-}" ] && bindkey "$terminfo[kcud1]" down-line-or-history 2>/dev/null || true
fi
```
Similarly, `autosuggest-accept` (`^f`) is only bound if `(( ${+widgets[autosuggest-accept]} ))` evaluates to true.

## Verification & Health Check

### 1. Check Widget Registration
Run the following in an interactive Zsh shell:
```zsh
zsh -i -c '
    echo "history-substring-search-up   : $(( ${+widgets[history-substring-search-up]} ))"
    echo "history-substring-search-down : $(( ${+widgets[history-substring-search-down]} ))"
    bindkey "^[[A"
    bindkey "^[[B"
'
```

Expected output (with plugin installed):
```text
history-substring-search-up   : 1
history-substring-search-down : 1
"^[[A" history-substring-search-up
"^[[B" history-substring-search-down
```

Expected output (minimal / fallback environment without plugins):
```text
history-substring-search-up   : 0
history-substring-search-down : 0
"^[[A" up-line-or-history
"^[[B" down-line-or-history
```

### 2. Run the Universal Zsh Bootstrap
```bash
./core/scripts/setup_zsh.sh
```
Should report:
```text
  ✓ Interactive Zsh environment initialized cleanly!
  ✓ History substring search widgets verified (history-substring-search-up/down)
```
